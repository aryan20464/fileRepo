Call to order
A meeting of IT-TSS Department with DevSecOps Team of PE-III was held at on 30-07-2026 regarding the discussion about false-positives in fortify scanning report in DevSecOps platform for our IDEA Applications.
Attendees: 
PE-III Devsecops team - Bibin PB, Guggilapu Suresh, Akshay Atmaram Vatharkar, Sachin Ashok Yadav 
IT-TSS Department – Siva Koppisetty, Gajvelly Chakravarthy	 		
Agenda:	
Information about timelines on inclusion of ISD department in the CI/CD automation of IDEA Applications for verification status of false positives identified in the fortify scanning report during scanning of application source code.
Prerequisite on application deployment:
DevSecOps platform handled by PE-III department is our bank’s application build and deployment automation platform that builds the application and deploys it to targeted servers there by eliminating manual tasks which are handled by the developer. The above process happens in stages where first stage is scanning of application code by Fortify SAST tool. Upon nil observations only will the application move forward into build stage further moving to deployment stage. 
Points of discussion:
1.	ISD is providing the security exit for all our IDEA applications after verifying the observations raised by them during testing process which are updated via EPM tool.

2.	The application code upon scanning with the fortify tool provided as a part of devsecops platform is giving us observations that are either fixed already during review by ISD or being identified by the tool without complete valid information with respect to the source code. Example: Validation of user takes place in the first step when a user request is received. Upon successful authentication & authorization, we are allowing the user to access to specific functionalities as per the access control mechanism which are not properly identified by the tool and are thrown as user not validated error. These kinds of observations are what we refer to as false-positives. 

3.	The devsecops team has informed us that there is no mechanism in place at present to verify the observations as false positives in the platform itself and there are talks going on with ISD department to onboard them in the above process to provide a decision on false positives. 

4.	Till the above process is completed we are suggested to inform to the devsecops team over email regarding observations which are identified as false positives in the scanning report by the application team for all environments from UAT to Production. 

5.	We will therefore be following the same procedure as informed to us above till there is a proper procedure in place till further communication.
