Yes, AKO (Avi Kubernetes Operator) supports multi-port access via the same ingress VIP. In version 22.1.6 of the Avi Load Balancer Controller and its compatible AKO releases, this is handled naturally across both Layer 7 (Ingress) and Layer 4 (Services) depending on how your backend services and routing paths are mapped.How to Implement Multi-Port Routing1. Layer 7 Ingress (Host/Path-based Routing to Multi-Port Services)If you have a single backend application (a multi-port Service), you can map multiple incoming paths or rules on the same Ingress FQDN/VIP to route to different service ports.When configuring a multi-port service inside your Ingress manifest, you must use strings that match the exact port names defined in your Kubernetes Service rather than port numbers:yamlapiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: multi-port-ingress
  namespace: default
spec:
  ingressClassName: avi-ingress
  rules:
  - host: myapp.avi.internal
    http:
      paths:
      - path: /web
        pathType: Prefix
        backend:
          service:
            name: my-multi-port-service
            port:
              name: web-port # Must match the Service's port name string
      - path: /api
        pathType: Prefix
        backend:
          service:
            name: my-multi-port-service
            port:
              name: api-port # Must match the Service's port name string
Use code with caution.2. Layer 4 Shared VIP (For LoadBalancer Services)If you are dealing with Layer 4 TCP/UDP workloads where multiple independent LoadBalancer services need to share the exact same Ingress VIP but listen on different ports, AKO handles this via the Shared VIP feature.To enable multiple L4 services to use the same VIP address:Ensure the services are deployed in the same Kubernetes namespace.Use AKO's annotation to pool the LoadBalancer traffic into a shared Avi virtual service instance.
